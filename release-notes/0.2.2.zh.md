# BKN Foundry 0.2.2

[English](0.2.2.md) | 中文

## 归档恢复任务可见性

日志和 Trace 的归档历史在最近 20 条之外保留旧的清理未完成任务；历史读取失败时
返回明确错误，避免被当作无记录。管理员可以定位阻止同类新归档的任务，并按原有
校验与安全清理流程恢复。不涉及 schema 或归档格式变更。关联：#2947、#2948。

## Cypher：精确数值返回

DECIMAL、NUMERIC 列（包括 `sum()` 结果）改为返回 JSON 数字，服务保留精确十进制位，
不经过 `float64` 转换；文本列保持字符串。原来假定 DECIMAL 为字符串的客户端需要接受
JSON 数字，并对大整数或高精度小数使用精确数值解码。已有 Trace 正文不重写。
关联：openbkn-ai/openbkn-ee#702。

## Context Loader：许可证中心配置

Retrieval Chart 支持 `licenseHub.url`，非空时渲染为 `BKN_SAFE_URL`。
社区默认值为空，不继承平台公共的 `bknSafe.url`。企业部署描述同时提供扩展工具定义和
许可证地址；工具发现和调用仍要求有效许可证及用户授权。关联：#3043。

## BKN 项目不支持从 0.2.1 升级

知识库和 BKN 项目在 0.2.1 是测试版，本版本不再安装 `bkn-project` 服务，也不提供从 0.2.1 的升级或数据迁移。
在 0.2.1 用过 BKN 项目的安装，升级前需要手动清理（先备份）：

1. 把 `bkn-project` 缩到 0 副本，删除它的全部 `t_bkn_project_*` 表。
2. 执行 `DELETE FROM deploy.t_schema_migration_task WHERE f_service_name='bkn-project'`。
3. 删除存储卷 `bkn-project-git`（或清空 `/data/git`）。
4. 从 `t_agent`、`t_agent_version`、`t_agent_prompt`、`t_agent_prompt_version` 删除
   `bkn-project-concept-extraction`、`bkn-project-document-extraction` 两个 Agent 及其提示词；
   不要动 bkn-agent 的迁移记录和其他 Agent。
5. 升级。

0.2.1 项目在 bkn-backend 发布的网络、抽取出的 Dataset 和知识库保留登记不会被删除，
不再需要的由管理员清理。

## Chart 默认值：依赖服务凭据

Chart 与配置默认值中不再带有历史遗留的厂商默认用户名，改为与 openbkn-deploy
一致的默认值：

- MariaDB 用户 `openbkn`：core-data-migrator、sandbox 两个 Chart。
- Kafka 用户 `kafkauser`：mf-model-manager 的 Chart、mf-model-api 的配置默认值，
  以及 agent-operator-integration 的本地配置（`mq_config.yaml`）。

sandbox、mf-model-manager 两个 Chart 中的占位密码改为默认为空。

需要做的：

- 通过 openbkn-deploy 安装的环境不受影响：它会显式传入
  `depServices.{rds,opensearch,mq}` 凭据。
- 手动 `helm install` / `helm upgrade` 必须显式传入 `depServices` 凭据（`-f`
  values 文件或 `--set`）。依赖旧 Chart 默认值的升级会渲染出新的默认值，可能
  无法连接；请使用 `--reuse-values` 或补齐这些值。
- 仍在使用历史默认密码的环境（MariaDB、OpenSearch、Kafka），应当轮换密码，并把
  新凭据显式传入。
