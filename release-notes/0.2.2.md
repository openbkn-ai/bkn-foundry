# BKN Foundry 0.2.2

[中文](0.2.2.zh.md) | English

## BKN projects: the knowledge base is a professional feature

Building a BKN project from documents is part of the **professional edition**
(openbkn-ee) from 0.2.2 on: choosing knowledge-base sources, extracting concepts
from documents, building and accepting document instances, publishing them with
a release and refreshing them. The open-source community edition keeps modelling
from structured data — drafting from tables, candidates, decisions, scenarios,
releases, switching and rollback — and the extension points the professional
edition uses. In the community edition the knowledge-base entries stay hidden
and their API answers 404, as before.

The professional edition creates its own tables and Agents with the
`bkn-project-ee migrate` command, run before the service starts.

### Chart values

The `bkn-project` chart no longer has `knowledgeBase.url`, `datasetStorage.*`
or `config.kbRefresh`; values that still set them are ignored. A professional
deployment passes its settings (`KB_API_URL`, `BKN_PROJECT_DATASET_ACCOUNT_ID`,
`BKN_PROJECT_DATASET_CATALOG_ID`, `BKN_PROJECT_KB_REFRESH_*`) through
`extraEnv`, and runs `bkn-project-ee migrate` through `initContainers`.

## No upgrade from 0.2.1 for BKN projects

The knowledge base and BKN projects were beta in 0.2.1. 0.2.2 installs them
fresh; there is no upgrade or data migration from 0.2.1. An installation that
used BKN projects in 0.2.1 is cleaned by hand before upgrading (back up first;
the steps are the same for both editions):

1. Scale `bkn-project` to 0 replicas and drop its tables: every
   `t_bkn_project_*` table.
2. `DELETE FROM deploy.t_schema_migration_task WHERE f_service_name='bkn-project'`.
3. Delete the volume `bkn-project-git` (or empty `/data/git`).
4. Delete the Agents `bkn-project-concept-extraction` and
   `bkn-project-document-extraction` with their prompts from `t_agent`,
   `t_agent_version`, `t_agent_prompt` and `t_agent_prompt_version`; leave the
   bkn-agent ledger and every other Agent alone.
5. Upgrade. The schema is created as on a fresh install; the professional
   edition then runs its migration.

Networks a 0.2.1 project published in bkn-backend, Datasets it extracted and
knowledge-base retention holds stay where they are; an administrator removes
those no longer wanted.
