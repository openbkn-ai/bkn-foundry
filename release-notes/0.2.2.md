# BKN Foundry 0.2.2

[中文](0.2.2.zh.md) | English

## Cypher: exact numeric results

DECIMAL and NUMERIC columns, including `sum()` results, now return JSON numbers
instead of strings. The service preserves their decimal digits without a
`float64` conversion; text columns remain strings. Clients that assumed a string
for DECIMAL must accept a JSON number and use an exact numeric decoder for large
integers or high-precision decimals. Existing Trace payloads are not rewritten.
Related: openbkn-ai/openbkn-ee#702.

## Context Loader: licence hub configuration

The Retrieval Chart supports `licenseHub.url`, rendered as `BKN_SAFE_URL` when
nonempty. Community defaults remain empty and do not inherit the shared platform
`bknSafe.url`. Enterprise delivery profiles supply the hub address together with
their extension definitions; discovery and invocation still require a valid
licence and user authorization. Related: #3043.

## No upgrade from 0.2.1 for BKN projects

The knowledge base and BKN projects were beta in 0.2.1, and this release no
longer installs the `bkn-project` service. There is no upgrade or data migration
from 0.2.1. An installation that used BKN projects in 0.2.1 is cleaned by hand
before upgrading (back up first):

1. Scale `bkn-project` to 0 replicas and drop its tables: every
   `t_bkn_project_*` table.
2. `DELETE FROM deploy.t_schema_migration_task WHERE f_service_name='bkn-project'`.
3. Delete the volume `bkn-project-git` (or empty `/data/git`).
4. Delete the Agents `bkn-project-concept-extraction` and
   `bkn-project-document-extraction` with their prompts from `t_agent`,
   `t_agent_version`, `t_agent_prompt` and `t_agent_prompt_version`; leave the
   bkn-agent ledger and every other Agent alone.
5. Upgrade.

Networks a 0.2.1 project published in bkn-backend, Datasets it extracted and
knowledge-base retention holds stay where they are; an administrator removes
those no longer wanted.

## Chart defaults: dependency credentials

The legacy vendor default user names are gone from the chart and config
defaults, replaced with the openbkn-deploy defaults:

- MariaDB user `openbkn`: core-data-migrator and sandbox charts.
- Kafka user `kafkauser`: mf-model-manager chart, mf-model-api config default,
  and the agent-operator-integration local profile (`mq_config.yaml`).

The placeholder passwords in the sandbox and mf-model-manager charts now
default to empty.

What to do:

- Installs done with openbkn-deploy are unaffected: it passes
  `depServices.{rds,opensearch,mq}` credentials explicitly.
- A manual `helm install` or `helm upgrade` must pass `depServices` credentials
  explicitly (`-f` values file or `--set`). An upgrade that relied on the old
  chart defaults will render the new defaults and may not connect; use
  `--reuse-values` or supply the values.
- An environment that still uses the legacy default password for MariaDB,
  OpenSearch or Kafka should rotate it, then pass the new credentials.
