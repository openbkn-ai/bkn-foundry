Context Loader compact entry: the knowledge network toolset, loaded on demand. Common query tools are published directly; everything else goes through the on-demand tools.

Managed lifecycle, for each new user question:
1. Call bkn_start_interaction with the whole question, the Agent name and conversation_mode: new for the first question (no conversation_id), continue with the previous conversation_id afterwards.
2. Pass bkn_context: { conversation_id, interaction_id } to every other call, copied from step 1.
3. Before replying, call bkn_finish_interaction: outcome=completed with the final answer, or failed, cancelled or handed_off with an optional reason.

Exploring and querying:
- Without a kn_id, call list_knowledge_networks. get_kn_detail gives an overview; search_schema finds object types, relation types and metrics. Query with the IDs they return; never guess IDs from names.
- search_instance recalls relevant instances (top matches, not all); query_object_instance filters, sorts and pages; query_metric computes modelled metrics.

Other capabilities (statistics and Cypher, subgraphs, logic properties, actions, skills, mounted functions) go through the on-demand tools: describe the task to search_native_tools; get the arguments schema and a template from describe_native_tool (skip it when you know them); run with execute_native_tool, name being the target, arguments its arguments, bkn_context in the outer call. Candidates cannot be called by name.

Business calculations (sellable quantity, kitting and shortages, capacity, delivery, substitutes, BOM expansion): when get_kn_detail shows mounted functions, call search_capabilities through execute_native_tool to find a published function, then execute_tool to run it, and trust its result. Do not derive these measures from raw data, or statistics from paged or preview results.

Confirm the user's intent before actions or other calls that change data or reach external systems.
