## 一段脚本解决整个问题

每发起一次 run_code 就是一次往返。先跑一次看结构、再跑一次取数、再跑一次聚合，
与逐个调用工具没有区别——探查、求解、以及你依赖的数据口径，要串在同一段脚本里。

多跑一轮最常见的原因不是想不出解法，而是**对数据口径有误解**（以为只有男足却混着
女足，以为球队名唯一却有 West Germany 与 Germany 两条）。把口径和答案一起打出来，
即使判断错了，改对它所需的信息也已经在手里了：

```python
detail = get_kn_detail(kn_id=kn)                       # 结构直接喂给下一步
ot = next(o for o in detail["object_types"] if "进球" in o.get("name", ""))
print("口径:", run_sql(sql="SELECT DISTINCT tournament_name FROM {{.<resource_id>}}")["entries"][:20])
print("答案:", run_sql(sql="SELECT team_name, COUNT(*) c FROM {{.<resource_id>}} GROUP BY team_name ORDER BY c DESC LIMIT 5")["entries"])
```

不确定的地方用代码兜住而不是回到对话：取值一律 `.get()`，可能失败的分支用
try/except 包住并 print 出关键中间信息。

## 能下推的聚合一律下推

计数、求和、分组、排序、Top-N 这类，**优先写一条 `run_sql`**，让数据库算完只回结果。
不要用 `query_object_instance` 拉 5000 行回来自己数——那既慢又受 `limit` 截断，
统计口径会悄悄错。

沙箱里的 pandas、numpy、scipy、sqlite3 与全部标准库，留给 SQL 表达不了的部分：
跨数据源关联、非 SQL 数据源、按中间结果分支、扇出。那些才是代码模式真正的用武之地。

## 工作目录与大结果

回到你面前的只有 stdout，**不要把大结果打印出来**：写进文件，再打印行数、字段名、
头部几行这类足以判断下一步的信息。

当前目录已切到本次会话专属的工作目录（`WORKDIR` 指向它），**用相对路径读写**，
不要写 `/workspace/xxx`——那是所有会话共用的根目录，会撞名。落盘的文件在同一对话
的多次执行之间保留，下一段脚本可以直接接着用（仍要 `exists()` 判断：换了对话，或
上一段在落盘前就失败了，文件就不在）。

## 执行 shell 命令

`run_shell` 共用这个工作目录，用来单独看一眼文件。但只要 shell 是解题过程的一环，
就写在这段脚本里，不要为它单开一轮：

```python
import subprocess
print(subprocess.run("wc -l rows.jsonl", shell=True, capture_output=True, text=True).stdout)
```

## 参数写不准时

完整 schema 在每个函数的 docstring 里，**在同一段脚本里** `help(fn)` 自查后接着往下写，
不要为了看文档单独跑一轮：

```python
help(query_object_instance)
```

特别是 `condition` 的 `operation`：`match` / `knn` 能否使用取决于该属性的
`condition_operations`（见 `get_object_types` 返回），从 `type` 推不出来。

## 错误处理

调用失败抛 `ToolError`，message 为服务端原文的 JSON，形如：

```json
{"error":{"code":"...","message":"...","required_action":"...","retryable":false}}
```

**先读 `retryable` 再决定下一步。** 为 false 表示同样的请求再发一次仍会失败——
换参数、换工具，或者把这条错误原样 print 出来交回，不要重试。原地重试三次只是把
同一个失败抄三遍，既拖慢一轮又什么都没换来。

`required_action` 有值时按它做（例如提示先查某个工具）。属于参数写错的（字段名
不存在、算子不支持），在同一段脚本里改完接着跑，不必回到对话轮次。

不要用 `try/except` + `pass` 把错误吞掉：你看不到的东西没法修，而调用方只会
收到一段没有解释的空输出。
