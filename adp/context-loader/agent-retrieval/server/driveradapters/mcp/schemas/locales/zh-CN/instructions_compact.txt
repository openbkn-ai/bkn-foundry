ContextLoader：常用查询直接调用，其他工具按需加载。

受管交互流程（每个新的用户问题）：
1. 调用 bkn_start_interaction，传入完整问题、当前 Agent 名称和 conversation_mode。首个问题用 new，不传 conversation_id；后续问题用 continue，并传入上次返回的 conversation_id。
2. 每次业务调用都把 start 返回的两个真实 ID 放入 bkn_context；关闭 Trace 采集时也一样。start 未返回 ID 时先重试 start，不调用业务工具。
3. 回复前带真实 interaction_id 调用 bkn_finish_interaction：completed 带 answer，否则 failed/cancelled/handed_off。将 _meta trace 的 partial_reasons 传入 finish；宿主丢弃 _meta 时读取独立降级诊断块。

探索与查询：
- 不知道 kn_id 时先 list_knowledge_networks；get_kn_detail 看概览，search_schema 找类和指标，用返回的真实 ID 查询。
- 自然语言召回实例用 search_instance（相关性 Top-K，不是全部）；按条件取数、排序、翻页用 query_object_instance；已建模指标用 query_metric。
- 聚合、计数、排名、分组和跨对象关联用 run_cypher（只读 Cypher，标签写对象类、关系写关系类、属性写逻辑属性名，聚合按 RETURN 其余列自动分组），一条查询完成，不要用 query_object_instance 拉多页后自行统计，总数只取同一过滤条件的 total_count 或聚合结果；口径已建成指标的走 query_metric。
- 已知路径模板（经过哪些对象类和关系类）批量取数用 query_instance_subgraph。

- 其他能力经按需工具：search_native_tools 找工具；有 ready 就按其 schema/template 调 execute_native_tool，否则先 describe_native_tool。name 填目标工具，arguments 填参数，bkn_context 放外层；候选不能按名称直调。

- get_kn_detail 有挂载函数时，先经 execute_native_tool 调 search_capabilities 查与问题相符的已发布函数；有就按其 call 调 execute_tool，以其结果为准，不要改用原始、分页或预览数据代替；函数失败或不适用才走通用查询并说明原因。按顶层 comment 的路由、指标和时间基线作答。

执行行动等会修改数据或调用外部系统的操作，先确认用户的意图。
