Vega Proxy Resource Read (0.1.0)

Download OpenAPI specification:

Cluster-internal read endpoints used by ontology-query after it resolves a published knowledge-network model to a physical Vega resource.

Vega is the final policy enforcement point. Before every physical read it verifies that the managed proxy account is active, still belongs to the stated knowledge network, and currently has the exact resource permission in bkn-safe. These checks are not cached.

Only schema inspection and filtered resource-data queries are exposed. This surface does not provide resource discovery, raw SQL, write, administration, build, or task operations.

All identity and BKN context headers are trusted workload credentials. They must be supplied only by ontology-query over the cluster-internal network; they are not accepted as end-user authentication on the public API.

Read a resource schema for strict dependency validation

Cluster-internal endpoint used by bkn-backend after it derives a binding target from the candidate model. The caller identity is the effective delegator returned by bkn-safe preflight. Vega rechecks exactly the requested view_detail or query_data operation and returns only the resource identity, name, and schema. It does not expose the unrestricted internal resource detail API.
