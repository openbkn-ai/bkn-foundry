DiscoverTask (0.1.0)

Download OpenAPI specification:

APIs for Vega Backend resource-discovery tasks.

A DiscoverTask is an execution audit record created through one of three paths:

  • Manual trigger: POST /catalogs/{id}/discover, documented at the end of this specification.
  • Scheduled trigger: a worker starts it from a DiscoverSchedule; see discover-schedule.yaml.
  • Resource refresh: POST /resources/{id}/discover; see resource.yaml.

queue_priority is a read-only integer computed by the server; larger values have higher priority. The default priorities are 10 for scheduled catalog discovery, 20 for manual catalog discovery, and 30 for resource refresh. Workers dequeue tasks strictly by priority and execute tasks for the same catalog serially.

The worker advances the state machine (pending → running → completed/failed/cancelled) in one direction. Users cannot cancel, retry, or restart a task. The public API exposes only list, get, and cleanup operations.

Bulk deletion follows the endpoint rules in [vega-backend/CLAUDE.md]: IDs are passed as a comma-separated path parameter to DELETE /discover-tasks/{ids}. Parent-resource filters use query parameters such as catalog_id, schedule_id, and resource_id; nested list endpoints are not provided.

List discovery tasks

Returns paginated discovery tasks and supports filtering by catalog_id, resource_id, schedule_id, status, strategy, and trigger_type.

Delete discovery tasks atomically

The operation is atomic: deletion starts only after every ID passes validation. If any validation fails, nothing is deleted.

Validation order:

  1. If any ID is pending or running, return 409 VegaBackend.DiscoverTask.HasRunningExecution with { running_ids: [...] } in error_details. This status check cannot be bypassed because deleting a task while a worker writes it would leave orphaned data. Wait until the task reaches completed, failed, or cancelled.
  2. If any ID does not exist and ignore_missing is false, return 404 VegaBackend.DiscoverTask.NotFound with { missing_ids: [...] } in error_details.
  3. If all IDs pass, delete them and return 204.
Authorizations:
OAuth2
path Parameters
id
required
string

DiscoverTask ID. DELETE accepts a comma-separated list of IDs.

query Parameters
ignore_missing
boolean
Default: false

Relaxes the existence check: missing IDs are treated as already deleted and silently skipped, while other IDs are deleted normally. This does not bypass the pending/running check.

Manually trigger catalog resource discovery

Triggers resource discovery for the specified catalog. Asynchronous: the server creates a DiscoverTask with trigger_type=manual, immediately returns its task ID, and lets a worker perform discovery asynchronously. Poll GET /discover-tasks/{id} with the returned ID to observe progress.

The optional body is {"strategy":"full_sync|create_only|cleanup_only"} and defaults to full_sync. This RPC-style nested endpoint represents an action on a catalog rather than creation of a top-level task.

Only catalogs with type=physical are supported. A logical catalog returns 400.
