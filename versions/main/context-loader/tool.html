已发布工具的检索与调用 (0.1.5)

Download OpenAPI specification:

把执行工厂里已注册、已发布的函数工具（Toolbox Tool，metadata_type=function） 交给调用方使用：search_tools 找到工具并拿回业务入参契约，execute_tool 以调用者 自己的身份执行它。

search_tools 目前是列举加字面过滤，不是语义召回。执行工厂没有跨工具箱的工具 枚举端点，也还没有可供 embedding 的工具数据集，所以本接口按当前账户可见的已发布 工具箱逐个取回已启用工具，再按名称、说明、使用规则与工具箱名做大小写不敏感的子串 匹配。「能算汇率的工具」这类问法答不了，换关键词或留空 query 通览更有效。契约按 「传检索词、拿有界列表」写，等 #1009 的工具数据集落地后换掉排序实现即可，调用方无感。

可见性与权限押在下游：两条接口都带调用者原始令牌打执行工厂的公开 API，工具箱是否 对该账户可见、工具是否允许执行由执行工厂判定，Context Loader 不代为放行。

execute_tool 有不可回滚的副作用：注册进来的函数可以对外部系统写入。调用前先读 search_tools 返回的 description 与 use_rule。服务端先在「当前账户可调用的已启用 工具」列表里核对 tool_id，不在其中直接 400，不会打到执行代理。

托管 Interaction：请求体里的 bkn_context 可选。带上时，conversation_id 与 interaction_id 会随调用透传到执行工厂，被调函数因而落在同一个 Interaction 下， 证据链完整；不带则只执行、不归因。

认证：Authorization: Bearer <token>（OAuth access token 或 bak_ AppKey）。

Tool

检索可调用的已发布函数工具

返回当前账户可调用的已发布函数工具。每条命中都带 tool_id、toolbox_id 与裁剪 过的 input_schema（只保留业务入参，服务地址等传输信息不下发），可直接用于构造 execute_tool 调用。

limit 默认 20、上限 100：每条命中都带一份入参 schema，调大会显著占用上下文。 命中数超过 limit 时 truncated=true 并给出 message。

单个工具箱取列表失败时跳过该箱而不是整体失败：一个被撤销或损坏的工具箱不该让 调用方看不到其余所有工具。

空结果是 200 不是错误：无匹配时 tools: [] 并带 message 说明。

执行一个已发布函数工具

以调用者身份执行工具，返回工具的原始响应。

toolbox_id 与 tool_id 必须取自 search_tools；arguments 按其返回的 input_schema 填，只放业务参数——令牌、会话 id 等传输信息由平台携带，写进 arguments 既不生效也会被记进调用参数。

函数自身报错同样是 200：调用成功不等于业务成功，需读响应体判断。

工具已停用、所属工具箱未发布，或当前账户无权访问时返回 400，message 说明原因， 请求不会打到执行代理。
