CypherQuery (0.1.0)

Download OpenAPI specification:

Read-only Cypher queries over the instance data of a knowledge network. A query is compiled into a single SQL statement and executed through vega-backend, so the subset accepted here is what compiles that way: one MATCH over a single path, a WHERE over properties, and a projection of properties and aggregates of them. Everything else is refused by name rather than approximated. Paging is written in the query itself with SKIP and LIMIT; there is no paging parameter. Exposed under /api/bkn-backend/v1 (OAuth2) and /api/ontology-manager/v1 (alias), with the branch query parameter defaulting to main.

CypherQuery

Run a read-only Cypher query

Compiles a Cypher query against the knowledge network's model and returns the rows it produces. Requires application/json content type and the query_data operation on each object type and relation type the query names; a network-wide query_data grant covers them, since the child operation inherits from its parent network. Each resource the statement reads is additionally checked for view_detail by vega-backend under the caller's own identity.

A concept the caller may not query is absent from the model the query is compiled against, so naming it reads as an unknown label rather than as a refusal: this endpoint cannot be used to find out what a model contains. A caller who may read nothing in the network gets 403.

Labels and relationship types accept either the id or the name of the object type or relation type. Properties are addressed by property name; display names and logic properties are not accepted. A query that does not write its own LIMIT is capped at 1000 rows, and a LIMIT above 10000 is refused rather than silently reduced.

The generated SQL is not returned: it names physical tables and columns, which the caller is not entitled to just because they may read the data.

Values for the $name references in the query. A parameter is a value and never an identifier: it can change which rows come back, never which resource or column is read. Strings, numbers and booleans are accepted; a null is refused, because IS NULL says that and a comparison against null never matches.

query
required
string <= 8192 characters

The Cypher query. Supported shape: MATCH (a:Label [{property: value, ...}]) [-[:RELATION]-(b:Label) ...] [WHERE ] RETURN [DISTINCT] a.property | aggregate(a.property) [AS alias], ... [ORDER BY a.property | alias | aggregate(a.property) [DESC]] [SKIP n] [LIMIT n]

A condition compares a property with =, <>, <, >, <= or >= against a literal or a parameter, or tests it with IN [ ... ], IS NULL or IS NOT NULL. Conditions combine with AND, OR and NOT, and parentheses group them. XOR is not supported.

Aggregates are count, sum, avg, min and max, each also in its DISTINCT form, plus count(*). Cypher has no GROUP BY: aggregating anything groups by everything else the query returns. A grouped or DISTINCT result can only be sorted by a value it returns.

A MATCH may contain several comma-separated paths, and a query may contain several MATCH clauses; both mean one shape. A variable written twice is the node it named the first time, which is how two paths meet, and paths that share no variable are a cartesian product. The first mention of a node names its object type; a later one may omit the label but must not contradict it.

A path may contain several relationships. Each names exactly one relation type and may be written -[:R]->, <-[:R]- or undirected as -[:R]-; each node names exactly one object type and may carry an inline property map, which means the equalities it stands for.

Cypher forbids one MATCH from traversing the same relationship twice, and that is enforced: within one MATCH, every pair of hops over one relation type must differ in its source row or its target row, which needs those object types to have a primary key. Where one of the hops is undirected the requirement cannot be stated, and the query is refused rather than answered with paths Cypher would not return. Hops in different MATCH clauses are not compared: writing MATCH (a)-[:R]->(b) MATCH (a)-[:R]->(c) is how one asks for every pair of things a reaches, b and c being the same included. One query's patterns may hold at most eight relationships and nine nodes, because each relationship is a join and each node is a table -- one that no relationship reaches is joined to the rest by nothing -- and the row limit bounds what comes back rather than what it costs to produce.
