BKN 知识网络 · 事件 API (0.1.0)

Download OpenAPI specification:

Events of a knowledge network. An event records something that happened in the business: a rule found an object in an abnormal state (source rule), or a person reported something (source report). Events belong to the network, not to an application. Applications follow a network's events through the change feed and handle them in their own tasks.

Each kind of event is an event class: an object type of the network whose kinds include event, maintained through the object type API (object-type.yaml) and carried in BKN packages (BKN specification §6.9). Its event configuration holds the source, the object type the events are about (subject), a default severity, a merge window and a handling note. The platform keeps the class's data source (a dataset that copies the class's events), its properties, keys and its relation {id}_subject to the subject. event_type in this API is the ID of the class.

Events are written and read against the event classes of the version the network runs: the published version that is running in a versioned network, its main branch otherwise. A class only in the draft has no events until the draft is published.

The module serves from the professional edition up. Without the license every route of this API, internal ones included, answers 404 as a path the server does not have; the capability snapshot tells what the edition lacks.

Authorization

Every operation checks one knowledge-network permission after confirming that the network exists.

Operations Permission on the knowledge network
List and get events, count occurrences, report an event, verify / reject / close / reopen an event, list and record rule checks query_data

A caller without the permission gets 403. The change feed carries no identity and checks no permission. See ../knowledge-network-authorization.md.

Authentication and the internal face

The routes under /api/bkn-backend/v1 require an OAuth2 bearer token (an AppKey is not accepted). Each of them has a twin under /api/bkn-backend/in/v1 with the same method, parameters, body and response. The twin takes the caller from the x-account-id and x-account-type request headers instead of a token and is reachable only inside the cluster. The one internal-only route is the change feed GET /api/bkn-backend/in/v1/knowledge-networks/{kn_id}/event-changes, which applications such as Workshop read to follow a network's events.

Behaviour

  • Events are kept on the network, not on a branch. The network is looked up on its main branch; an unknown network is 404 BknBackend.KnowledgeNetwork.NotFound.
  • Request bodies are JSON of at most 16 MiB; a larger body is 413 BknBackend.KnEvent.TooLarge. A field the API does not define is refused with 400 BknBackend.KnEvent.InvalidParameter. Responses are not cached. All times are Unix timestamps in milliseconds.
  • Statuses of an event: unverified, verified, rejected, duplicate, closed. The status describes the event itself; how an application handles it is recorded by that application.
  • A rule event class is fed by rule checks. The first check of an object that is not yet open creates a verified event (verified by rule). A check that finds an open event's object again only refreshes it. A check that covers an open event's object but does not hit it ends the abnormal period: the event becomes closed and gets ended_at. A rejected event is never reopened by a check, and a person's close does not end a rule event's period; a rule event ends only when its rule finds it over.
  • A reported event class is fed by reports. A report is unverified unless verify is true, which verifies it at once as the reporter. If the class has merge_hours above 0 and the report has an object_key, and an unverified or verified event of the same class and object has an occurred_at within the window, the new event is stored as duplicate with merged_into set to the first event.
  • An event class that has events cannot be deleted: the object type API answers 409 BknBackend.KnEvent.EventTypeInUse. Deleting a class leaves its dataset in place.
  • The change feed keeps every change to an event. The entries for a check that only refreshed an event (action checked) are removed after 7 days; the other entries are the events' history and are kept.
  • Names of the reporter, verifier and actors are resolved from the user directory when the change is written; if the directory is unavailable the name is left empty.

Resource IDs of knowledge networks use lowercase letters, digits, underscores and hyphens, start with a letter or digit, and contain at most 128 characters.

Pages are cursor based: pass the next_cursor of a page as cursor to get the next one; next_cursor is empty on the last page. from and to choose the events by when they occurred. An unknown status, a cursor that is not valid, or a from that is not before to is 400.

Report an event

Reports an event of a report event class. Requires query_data. The reporter is the caller.

The event starts unverified, or verified when verify is true. If the class's merge_hours is above 0, object_key is given and an unverified or verified event of the same class and object has an occurred_at within merge_hours of this one's, the new event is stored as duplicate (verify is then ignored) with merged_into set to the first matching event, and that event is returned too. occurred_at defaults to the time of the report. object_name defaults to object_key. detail is free JSON of at most 1 MiB and defaults to {}.

404 BknBackend.KnEvent.EventTypeNotFound when the version the network runs has no such class; 409 BknBackend.KnEvent.SourceMismatch if the class's source is rule.

Verify, reject, close or reopen an event

Takes an action on an event. Requires query_data. The body is optional; when present it may only hold reason. The caller is recorded as the actor in the event's history.

Action From status To status Reason
verify unverified verified (records the verifier) optional
reject unverified rejected required
close verified closed required
reopen closed verified required

A reopen is allowed for a closed reported event at any time, and for a closed rule event only while its rule has not ended it (ended_at is 0). Closing a reported event sets ended_at; reopening it clears it. Closing a rule event does not set ended_at. The actions field of an event lists what it allows now.

An action name other than the four above is 404 Public.NotFound. An action the status does not allow is 409 BknBackend.KnEvent.ActionNotAllowed, with error details {"action": "...", "status": "..."}. A missing required reason is 400.

Count event occurrences

Counts, for each event class, the events that occurred in a span. Requires query_data. Rejected and duplicate events do not count, nor does what a rule found already there on its first decision, or its first after the rule changed (backlog). open_count is how many of the counted events are unverified or verified; last_occurred_at is when the latest of them occurred. Classes with no occurrences have no entry; entries are ordered by class ID.

The span runs from from, inclusive, to to, exclusive. With neither, it is the seven days up to now; with from alone it runs up to now, with to alone it is the seven days before to. The response gives the span it counted. A from that is not before to is 400.

Record a rule check

Records one run of the rule of a rule event class and applies it to the class's events. Requires query_data. 404 BknBackend.KnEvent.EventTypeNotFound when the version the network runs has no such class; 409 BknBackend.KnEvent.SourceMismatch if the class's source is report.

A class that has a record-event action type in the version the network runs takes checks only from it: the platform runs it on its schedule and records its checks through the internal API, naming it in action_type_id (409 BknBackend.KnEvent.RecognitionMismatch for any other check, and for a check that names an action type the class does not have). The public API does not take action_type_id (400). The internal API takes the x-bkn-execution-id header, the action execution the check belongs to (1 to 40 letters, digits and -), and records it in the history of every event the check changes.

  • status: unknown means the rule could not decide. No event changes state; the open events of the class only get last_checked_at and check_status: unknown refreshed. The stored check keeps last_ok, the time of the last check that decided.
  • status: ok means the rule decided and hits is the complete result for the objects it read. A hit with no open event of the class for that key opens a new verified event; a hit whose object has an open event refreshes it (rule_version, attributes merged by property name, last_checked_at, check_status: ok); an open event whose object is not hit is closed. Duplicate keys in hits count once, the first one winning.
  • covered limits ok to the objects the rule read when it read only some: open events whose object_key is not listed are left as they are. Absent or null, the check covered all objects. An empty list covers none.
  • An event opened by the first ok check of a class, or by the first after its rule_version changed, is marked backlog: true: it records what had long been wrong.
  • Only events whose period is open (ended_at is 0) and that are not rejected take part in a check. A closed event whose period has ended is never changed by a check, so an object that is hit again opens a new event.
  • A closed event whose rule has not ended it does take part: a hit refreshes it, and a miss ends its period.

The event's title for a hit is the class name and the object name. hits has at most 20000 entries (413 beyond), each with a key of 1 to 250 characters. A hit's detail is written to the event it opens; a later check does not change it.

KnEventChange

Internal change feed

Read the change feed of a network's events

Internal, cluster only. Returns the changes to a network's events after a sequence number, so an application can follow them and handle the events in its own tasks. It takes no caller identity and checks no permission; the network must exist (404 otherwise).

Each write to an event appends one entry with a network-wide increasing seq. An entry carries the event's state after the write, without history. A page's entries are ordered by seq, ascending. To follow the feed, read with after set to the last_seq of the previous page and stop when entries is empty; last_seq then equals the after that was sent. Sequence numbers may have gaps, because the feed removes checked entries after 7 days.

action is one of reported, detected, recovered, recovered-after-update, checked, or the person's actions verify, reject, close, reopen. checked means a rule check only refreshed the detection fields of an open event.

path Parameters
kn_id
required
string <= 128 characters ^[a-z0-9][a-z0-9_-]{0,127}$

query Parameters
after
integer <int64> >= 0
Default: 0

Return entries with a sequence greater than this. A non-negative integer; defaults to 0, the start of the feed. A negative or non-numeric value is 400.

limit
integer <int64> [ 0 .. 1000 ]
Default: 500

Maximum entries in the page. 0 or absent gives 500; a value above 1000 is reduced to 1000. A negative or non-numeric value is 400.
