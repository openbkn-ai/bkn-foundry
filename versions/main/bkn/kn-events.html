BKN 知识网络 · 事件 API (0.1.0)

Download OpenAPI specification:

Events of a knowledge network. An event records something that happened in the business: a rule found an object in an abnormal state (source rule), or a person reported something (source report). Events belong to the network, not to an application. Applications follow a network's events through the change feed and handle them in their own tasks.

An event type, identified by code, says how one kind of event is recognised in the network: its source, the object type it is about (subject), a severity, a merge window and, for a rule type, the rule. Every event type has an event class: an object type of the same network named after the event type, whose objects are the events of that type, so events can be queried, related and authorized like the network's other objects. The platform writes a dataset behind the class, a copy of the events. object_type_id and dataset_id on the event type are the IDs of the class and its dataset; they are empty for a type whose class has not been created yet. The class is created with the event type and is written again when the type's name or subject changes. In a versioned network the class is written into the draft. The class is a platform-managed object type with the ID object_type_id; do not change it through the object type API.

Authorization

Every operation checks one knowledge-network permission after confirming that the network exists.

Operations Permission on the knowledge network
List and get event types view_detail
Create, update and delete event types modify
List and get events, report an event, verify / reject / close / reopen an event, list and record rule checks query_data

A caller without the permission gets 403. The change feed carries no identity and checks no permission. See ../knowledge-network-authorization.md.

Authentication and the internal face

The routes under /api/bkn-backend/v1 require an OAuth2 bearer token (an AppKey is not accepted). Each of them has a twin under /api/bkn-backend/in/v1 with the same method, parameters, body and response. The twin takes the caller from the x-account-id and x-account-type request headers instead of a token and is reachable only inside the cluster. The one internal-only route is the change feed GET /api/bkn-backend/in/v1/knowledge-networks/{kn_id}/event-changes, which applications such as Workshop read to follow a network's events.

Behaviour

  • Events are kept on the network, not on a branch. The network is looked up on its main branch; an unknown network is 404 BknBackend.KnowledgeNetwork.NotFound.
  • Request bodies are JSON of at most 16 MiB; a larger body is 413 BknBackend.KnEvent.TooLarge. A field the API does not define is refused with 400 BknBackend.KnEvent.InvalidParameter. Responses are not cached. All times are Unix timestamps in milliseconds.
  • Statuses of an event: unverified, verified, rejected, duplicate, closed. The status describes the event itself; how an application handles it is recorded by that application.
  • A rule event type is fed by rule checks. The first check of an object that is not yet open creates a verified event (verified by rule). A check that finds an open event's object again only refreshes it. A check that covers an open event's object but does not hit it ends the abnormal period: the event becomes closed and gets ended_at. A rejected event is never reopened by a check, and a person's close does not end a rule event's period; a rule event ends only when its rule finds it over.
  • A reported event type is fed by reports. A report is unverified unless verify is true, which verifies it at once as the reporter. If the type has merge_hours above 0 and the report has an object_key, and an unverified or verified event of the same type and object has an occurred_at within the window, the new event is stored as duplicate with merged_into set to the first event.
  • Event type deletion is refused with 409 while the type has any event, or while its event class is used by other definitions of the network.
  • The change feed keeps every change to an event. The entries for a check that only refreshed an event (action checked) are removed after 7 days; the other entries are the events' history and are kept.
  • Names of the reporter, verifier and actors are resolved from the user directory when the change is written; if the directory is unavailable the name is left empty.

Event type codes match ^[a-z0-9][a-z0-9_.-]{0,63}$. Resource IDs of knowledge networks use lowercase letters, digits, underscores and hyphens, start with a letter or digit, and contain at most 128 characters.

Create an event type

Creates an event type and its event class (an object type, with a dataset behind it) in the knowledge network. Requires modify. The class is created first; if it cannot be created the event type is not created.

code is required and matches ^[a-z0-9][a-z0-9_.-]{0,63}$. source is required and cannot be changed later. If subject names an object type of the network that has a primary key, the class gets a relation to it, so an event reaches the object it is about.

409 BknBackend.KnEvent.EventTypeExisted is returned when the code is taken, when the class ID derived from the code is the class of another event type, or when the network already has an object type with that ID or with the same name as the event type.

Delete an event type

Deletes an event type, its event class and the class's dataset. Requires modify.

409 BknBackend.KnEvent.EventTypeInUse is returned when the type has any event (of any status), or when its class, or the class's relation, is used by other definitions of the network (the error details name the users). Nothing is deleted in that case. The dataset is deleted after the type is gone; a failure to delete it is logged and does not fail the request. In a versioned network the class is removed in the draft and the dataset is kept, since the published version still reads the class.

Report an event

Reports an event of a report event type. Requires query_data. The reporter is the caller.

The event starts unverified, or verified when verify is true. If the type's merge_hours is above 0, object_key is given and an unverified or verified event of the same type and object has an occurred_at within merge_hours of this one's, the new event is stored as duplicate (verify is then ignored) with merged_into set to the first matching event, and that event is returned too. occurred_at defaults to the time of the report. object_name defaults to object_key. detail is free JSON of at most 1 MiB and defaults to {}.

404 BknBackend.KnEvent.EventTypeNotFound for an unknown type; 409 BknBackend.KnEvent.SourceMismatch if the type is a rule type.

Verify, reject, close or reopen an event

Takes an action on an event. Requires query_data. The body is optional; when present it may only hold reason. The caller is recorded as the actor in the event's history.

Action From status To status Reason
verify unverified verified (records the verifier) optional
reject unverified rejected required
close verified closed required
reopen closed verified required

A reopen is allowed for a closed reported event at any time, and for a closed rule event only while its rule has not ended it (ended_at is 0). Closing a reported event sets ended_at; reopening it clears it. Closing a rule event does not set ended_at. The actions field of an event lists what it allows now.

An action name other than the four above is 404 Public.NotFound. An action the status does not allow is 409 BknBackend.KnEvent.ActionNotAllowed, with error details {"action": "...", "status": "..."}. A missing required reason is 400.

Record a rule check

Records one run of a rule event type and applies it to the type's events. Requires query_data. 404 BknBackend.KnEvent.EventTypeNotFound for an unknown type; 409 BknBackend.KnEvent.SourceMismatch if the type is a report type.

  • status: unknown means the rule could not decide. No event changes state; the open events of the type only get last_checked_at and check_status: unknown refreshed. The stored check keeps last_ok, the time of the last check that decided.
  • status: ok means the rule decided and hits is the complete result for the objects it read. A hit with no open event of the type for that key opens a new verified event; a hit whose object has an open event refreshes it (rule_version, attributes merged by property name, last_checked_at, check_status: ok); an open event whose object is not hit is closed. Duplicate keys in hits count once, the first one winning.
  • covered limits ok to the objects the rule read when it read only some: open events whose object_key is not listed are left as they are. Absent or null, the check covered all objects. An empty list covers none.
  • An event opened by the first ok check after a rule is set up, one with no earlier decided check, is marked backlog: true: it records what had long been wrong.
  • Only events whose period is open (ended_at is 0) and that are not rejected take part in a check. A closed event whose period has ended is never changed by a check, so an object that is hit again opens a new event.
  • A closed event whose rule has not ended it does take part: a hit refreshes it, and a miss ends its period.

The event's title for a hit is the type name and the object name. hits has at most 20000 entries (413 beyond), each with a key of 1 to 250 characters.

KnEventChange

Internal change feed

Read the change feed of a network's events

Internal, cluster only. Returns the changes to a network's events after a sequence number, so an application can follow them and handle the events in its own tasks. It takes no caller identity and checks no permission; the network must exist (404 otherwise).

Each write to an event appends one entry with a network-wide increasing seq. An entry carries the event's state after the write, without history. A page's entries are ordered by seq, ascending. To follow the feed, read with after set to the last_seq of the previous page and stop when entries is empty; last_seq then equals the after that was sent. Sequence numbers may have gaps, because the feed removes checked entries after 7 days.

action is one of reported, detected, recovered, recovered-after-update, checked, or the person's actions verify, reject, close, reopen. checked means a rule check only refreshed the detection fields of an open event.
