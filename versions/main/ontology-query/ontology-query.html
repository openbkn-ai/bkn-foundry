ontology-query (0.2.0)

Download OpenAPI specification:

Schema and data-query endpoints resolve trusted dependencies from the published main knowledge-network model and require the real caller's view_detail or query_data on every canonical {resource_type}:{kn_id}/{child_id} dependency before reading metadata or data. The service then resolves the knowledge network's active managed proxy; Vega performs the final corresponding resource permission check for that proxy through its restricted internal endpoint.

Action submission requires the caller's action_type.execute plus all input/target object dependencies' query_data. Tool Box or MCP execute belongs to the managed proxy and is checked again by the restricted execution endpoint. Proxy identity and target bindings are always server-derived from the current published main model. See ../knowledge-network-authorization.md and trusted-proxy-context.md.

查询已落库的 object_type 作用域 atomic 指标（定义见 bkn-backend MetricDefinition）。

定义内过滤 vs 查询时过滤

执行时将以下条件 按 AND 合并（不是覆盖）后下推到 Vega/resource：

  1. MetricDefinition.calculation_formula.condition（定义内口径，稳定 KPI）
  2. 本请求体 condition（查询时下钻 / 临时收窄）
  3. 由 time 或 time_dimension.default_range_policy 推导的时间范围条件（instant / 趋势查询时）

合并规则：语义上等价于 AND(definition.condition, request.condition, timeCondition)，任一侧为空则省略。 实现上为两层嵌套（先合并 definition 与 request，再与时间条件 AND），下推 filter 可能出现 sub_conditions 嵌套，而非扁平三元组。

analysis_dimensions 与 group_by

  • calculation_formula.group_by：定义内的固定分组基线，每次查询都会参与 group_by。
  • analysis_dimensions（请求体）：在指标 analysis_dimensions 白名单内的追加下钻维度，按请求顺序接在 group_by 之后；未知维度名忽略。
  • 趋势查询（time.instant 为 false 或省略，且提供 time.step）会额外追加时间分桶维度。

建模 CRUD 与能力矩阵见 bkn-metrics.yaml；对象类级总量指标应使用本接口，而非对象实例页的 logic-property 执行入口。
