Schema and data-query endpoints resolve trusted dependencies from the published main knowledge-network model and require the real caller's view_detail or query_data on every canonical {resource_type}:{kn_id}/{child_id} dependency before reading metadata or data. The service then resolves the knowledge network's active managed proxy; Vega performs the final corresponding resource permission check for that proxy through its restricted internal endpoint.

Action submission requires the caller's action_type.execute plus all input/target object dependencies' query_data. Tool Box or MCP execute belongs to the managed proxy and is checked again by the restricted execution endpoint. Proxy identity and target bindings are always server-derived from the current published main model. See ../knowledge-network-authorization.md and trusted-proxy-context.md. Instance and subgraph reads use ignore_local_index (default false) to bypass a resource's local index where supported. Applicability and operator support depend on the resource's query capabilities in Vega. This replaces the ineffective ignoring_store_cache parameter; no compatibility alias is provided. Object responses expose Vega's actual query_source (local_index or source) instead of search_from_index. Clients must migrate these names together with the server. The internal cursor digest encoding remains unchanged. Changing ignore_local_index requires a new query rather than continuing an existing cursor.

Knowledge-network versions

The data, schema and subgraph queries and the action endpoints accept kn_version (running, draft or a version number of a versioned knowledge network) and, with kn_version=draft, draft_revision. Without them the running version is read. The first read of a query from bkn-backend fixes the version, and every later bkn-backend call of the same query asks for exactly that version, so a publish or a draft edit during a query cannot mix two versions; if bkn-backend nevertheless answers from another version, the query fails with 409 OntologyQuery.KNVersion.Changed. A cursor is bound to the version it was read from: continue it with the same kn_version (and draft_revision), otherwise the cursor is refused as invalid. Paging never switches to the version of the cursor. The legacy branch parameter still accepts only main, which means the running version.

Bkn-backend refuses a request about a version in its own words and the refusal is returned unchanged, with its error code, also on endpoints that report a missing definition as 404: 404 BknBackend.KNVersion.VersionNotFound, 410 BknBackend.KNVersion.VersionPurged, 409 BknBackend.KNVersion.DraftRevisionMismatch, 400 BknBackend.KNVersion.NotVersioned or BknBackend.KNVersion.InvalidVersion, 403 BknBackend.KNVersion.EditionRestricted and 409 BknBackend.KNVersion.VersioningDisabling. A malformed kn_version or draft_revision, or draft_revision without kn_version=draft, is 400 OntologyQuery.KNVersion.InvalidParameter.

The managed proxy's grants cover the running version. A query that reads the draft or a version that is not running reads data with the caller's own identity, so Vega checks the caller's own permissions on the data resources instead of the proxy's.

Authorizations:
OAuth2
path Parameters
kn_id
required
string

业务知识网络ID

query Parameters
kn_version
string
Example: kn_version=draft

The knowledge-network version to read: running (default), draft, or a version number. Reading the draft needs modify on the network, any other version view_detail. On a network without versioning only running is accepted. Do not combine it with branch.

draft_revision
integer <int64> >= 0

With kn_version=draft, the draft revision the query expects. A different current revision is 409 BknBackend.KNVersion.DraftRevisionMismatch. Without it the query reads the draft as it is when the query starts and keeps that revision.

branch
string

分支名称

include_type_info
boolean

是否包含对象类信息，默认false，不包含

include_logic_params
boolean

包含逻辑属性的计算参数，默认false，返回结果不包含逻辑属性的字段和值

ignore_local_index
boolean

是否跳过资源的本地索引并查询数据源，默认 false；参数是否适用及 match/knn 等算子是否受支持，由 Vega 根据资源的查询能力决定。

exclude_system_properties
Array of strings
Items Enum: "_instance_id" "_instance_identity" "_display"

需要排除的系统字段列表。可选值：_instance_id（实例ID）、_instance_identity（实例唯一标识）、_display（显示值）。如果指定了某个字段，则在返回的对象数据中不包含该字段。可以传递多个值，例如：?exclude_system_properties=_instance_id&exclude_system_properties=_display
