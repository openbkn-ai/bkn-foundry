BKN Operation Audit (0.1.0)

Download OpenAPI specification:

Management operation facts on the modeling surface: who, in which knowledge network, did what to which resource, and whether it succeeded. Read-only — facts are written by the write endpoints as they handle a request, and there is no back-fill entrance.

Not the same thing as BKN Trace: Trace records an Agent's question-answering and retrieval chain, this records modeling and configuration changes (creating an object type, editing a metric, mounting a capability). Neither covers the other.

Bounded facts, not requests

A record holds the fields below and nothing else: no request body, no response body and no credentials. change_summary accepts only the keys changed_fields and status; any other key makes the whole record be rejected rather than truncated.

Visibility narrows by caller

Caller Sees
Administrator Everything
User with managed knowledge networks Records under those networks
Everyone else Only records where they are the actor

A caller in the third group asking for someone else's actor_id gets a 403 (BknBackend.OperationAudit.AccessDenied) rather than a result set quietly rewritten to their own — otherwise "no results" and "not allowed" would be indistinguishable.

The time range is mandatory

from and to are both required RFC3339 timestamps, from must precede to, and the span is capped at 30 days. Anything else is a 400. This is a guard against a full-table scan, not an optional convenience.

Paging uses the before_time + before_event_id cursor rather than an offset: the table grows newest-first, and offset paging would repeat or skip records while writes continue.

Actions and target types are closed vocabularies

The write path validates both against fixed sets, and a value outside them makes the whole record be dropped while the caller's business request still succeeds — the only trace is a line in the service log. Adding a verb or a target type means changing both allowedActions / allowedTargetTypes in server/common/operationaudit/store.go and the route rule table in driveradapters/operation_audit.go. Miss either one and the audit is silently lost.

Authentication: Authorization: Bearer <token> (an OAuth access token or a bak_ prefixed AppKey).

Prefix alias: the paths below are also registered under /api/ontology-manager/v1.

OperationAudit

Management operation audit (read-only)

List operation audit records

query Parameters
from
required
string <date-time>

Start of the range, inclusive, RFC3339. Required.

to
required
string <date-time>

End of the range, exclusive, RFC3339. Required, and at most 30 days after from.

actor_id
string

Filter by actor. A caller whose visibility is narrowed gets a 403 when asking for someone else's ID, not an empty result.

action
string (Action)
Enum: "create" "update" "delete" "import" "add_members" "remove_members" "enable" "disable" "attach" "detach"

Filter by action; see Action.

target_type
string (TargetType)
Enum: "knowledge_network" "object_type" "relation_type" "action_type" "metric" "risk_type" "concept_group" "action_schedule" "kn_capability_binding"

Filter by target resource type; see TargetType.

target_id
string

Filter by target resource ID. A batch operation records several IDs separated by commas.

outcome
string (Outcome)
Enum: "success" "failure" "denied"

Filter by outcome.

limit
integer <= 500
Default: 50

Page size, 50 by default, capped at 500. A larger value is capped, not rejected.

before_time
string <date-time>

Cursor: return only records older than this instant, RFC3339. Used together with before_event_id; both come from the previous page's next_before_time and next_before_event_id.

before_event_id
string

Second half of the cursor, ordering records that share one instant.
