Upload and import a BKN tar archive

Upload a BKN tar archive and import it as a business knowledge network. For the archive format, see docs/design/bkn/features/bkn_docs/SPECIFICATION.md

Authorizations:
OAuth2
query Parameters
branch
string
Default: "main"

Branch name. Defaults to main.

binding_policy
string
Default: "preserve"
Enum: "preserve" "detach"

Controls how environment-local bindings in the archive are imported. preserve keeps resource, Tool Box, and MCP identifiers and subjects them to proxy permission checks. detach removes those identifiers, including indirect-relation backing resources, while preserving the knowledge model topology so targets can be bound later through incremental APIs.

import_mode
string
Default: "normal"
Enum: "normal" "overwrite" "ignore"

Import mode. normal reports an error for duplicate concept names; overwrite replaces them; ignore skips them. Defaults to normal.

strict_mode
boolean
Default: true

Whether to validate that dependent objects exist. Defaults to true. When empty, the deprecated validate_dependency parameter is used.

validate_dependency
boolean
Deprecated
Default: true

Deprecated. Use strict_mode instead. This parameter is retained for compatibility and is read when strict_mode is empty.

Compare two knowledge network branches

Report what differs between two knowledge network branches, definition by definition and field by field. Both networks are named in the body: neither is the resource being addressed, and putting one in the path would suggest the comparison belongs to it.

Each side is authorized on its own, so a caller who may read one network and not the other is refused exactly as they would be asking for that network directly.

Definitions are paired by type and id. Two networks built independently share no definition ids — ids are generated per network — so their comparison degrades into "everything created, everything deleted". lineage reports that overlap up front, and fallback_by_name pairs the remainder by name when the caller opts in.

Definitions that are identical on both sides are counted in summary and left out of entries.

Authorizations:
OAuth2
Request Body schema: application/json
required
required
object (KNDiffSideRequest)
required
object (KNDiffSideRequest)
fallback_by_name
boolean
Default: false

Pair definitions by name once id matching is exhausted. A name match is a guess: two definitions can carry the same name and mean different things, so a paired entry reports both ids for a human to check, and an ambiguous name pairs with nothing.

include_unchanged
boolean
Default: false

Also return the definitions that are identical on both sides. They carry no changes — they are there to be listed, not read — and the counts in summary are the same either way. A caller that shows the whole model beside the differences asks for them; one that shows only what moved does not pay for them.

Responses

/api/bkn-backend/v1/bkns/diff

Count the data behind one object type on each side of a comparison

Report how much data sits behind two object types: the row count of each bound resource and the number of distinct primary keys in it.

This is a separate call from the comparison because it queries the customer's own database. A comparison opens without paying for it, and pays only for the object type someone actually opens.

Two numbers is the whole of it on purpose. Per-column statistics — null rates, value distributions — cost another pass over the table for every column, and this runs while someone waits with a comparison open.

same_resource is true when both object types are bound to the same resource. The two sides are then reading one table and every number matches by construction, which is not a finding about the data. missing_keys counts rows with a NULL in any primary key column: they identify no object at all. duplicate_keys counts the rows with a complete key beyond the first for each key: a non-zero value means the resource holds rows the model believes are the same object. The two are kept apart because they are different faults, and a row without a key must not read as a duplicate.

List resources

Lists resources by resource type with pagination on the unified resource platform. Currently supports resource_type=knowledge_network.

Authorizations:
OAuth2
query Parameters
resource_type
required
string
Value: "knowledge_network"

Resource type. The current implementation recognizes only knowledge_network, which represents a knowledge network. It maps to interfaces.RESOURCE_TYPE_KN.

Other values do not return an error. Instead, the default branch returns 200 with an empty response body. This is not an empty list: there is no body at all. An invalid value causes the client to fail JSON parsing or receive no data, rather than receive a 400 response.
