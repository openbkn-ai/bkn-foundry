Cypher 查询 (0.1.4)

Download OpenAPI specification:

用只读 Cypher 查知识网络：标签是对象类，关系类型是关系类，属性是逻辑属性名。 本服务不自带查询语言实现——它把请求带着调用方身份转给 bkn-backend，由那边按 知识网络的模型把 Cypher 编译成一条 SQL 下发，再把行返回来。

与其他查询入口的分工：

  • object-instance.yaml 的 query_object_instance： 单个对象类的平面过滤，不跨关系。
  • instance-subgraph.yaml 的 query_instance_subgraph / explore_subgraph：要的是子图（节点 + 边的拓扑）。
  • 本接口：要的是表（按路径过滤后投影出的行，可聚合、可排序、可分页）， 路径与条件写在一句 Cypher 里。
  • data-access.yaml 的 run_sql：绕开本体直查物理表。 本接口表达不了的口径（CTE、UNION、窗口函数）或资源没建成对象类时才落到那里。

不需要 resource_id，也不需要物理列名——名字全部取自 schema-search.yaml 的 search_schema 或 kn-explore.yaml 的 get_object_types / get_relation_types。

授权：由 bkn-backend 按调用方账户裁决——语句点名的每个对象类与关系类都要有 query_data（网络级授权会继承到其下的对象类与关系类），再往下 vega 对每个资源 校验读取权限。无权查询的概念在编译用的模型里直接不存在，写了只会报「未知标签」， 而不是「无权」，所以不能拿本接口探测模型里有什么。本服务只做转发，不放大调用方能 读的范围。

认证：Authorization: Bearer <token>（OAuth access token 或 bak_ AppKey）。

Cypher

对知识网络执行只读 Cypher

编译并执行一条只读 Cypher 语句。支持的子集：

  • MATCH：一个或多个 MATCH 子句；一个 MATCH 里可以写逗号分隔的多条路径。 同名变量指同一个节点；不共享变量的两部分是笛卡尔积。
  • 节点：变量首次出现时必须带标签（对象类 id 或名称），可带内联属性 {prop: value}。
  • 关系：-[:R]->、<-[:R]-、无向 -[:R]-，每条必须指名一个关系类； 一条查询的模式最多 8 条关系、9 个节点（不与其他节点相连的节点也各算一张表）。 关系变量（-[r:R]->）不支持。
  • WHERE：= <> < > <= >=、IN [...]、IS NULL / IS NOT NULL， 用 AND / OR / NOT 组合，可加括号。值可写 $name 参数。
  • RETURN：属性、AS 别名、DISTINCT，以及 count / sum / avg / min / max（含 count(*) 与 DISTINCT 形式）。有聚合时按 RETURN 中其余 列自动分组——这是 Cypher 的隐式 GROUP BY，无需也不能自己写 GROUP BY。
  • ORDER BY / SKIP / LIMIT：ORDER BY 可用属性、返回列名或聚合。结果被聚合 或 DISTINCT 折叠后，只能按返回的值排序。

不支持（会被拒绝，报错指名是哪个语法与位置）：OPTIONAL MATCH、WITH、 UNION、变长路径 [:R*1..3]、XOR、STARTS WITH / CONTAINS / ENDS WITH、 返回整个节点、函数调用与算术表达式、写操作（CREATE / MERGE / DELETE / SET / REMOVE）。

行数：不写 LIMIT 默认返回 1000 行；LIMIT 不得超过 10000。

关系唯一性：按 openCypher 语义，同一条路径里共用同一关系类的多跳互不相同， 编译器会自动补上主键不等的条件，调用方不必自己写。

required
object (BKNContext)

BKN Trace business-provenance context identifying the business conversation and interaction to which this call belongs. Required on REST APIs.

Both required child fields are server-issued handles and must not be invented by the caller:

  • conversation_id: obtained from the Context Loader MCP tool bkn_start_interaction on the first turn
  • interaction_id: obtained from the Context Loader MCP tool bkn_start_interaction

These handles are available only through the provenance MCP tool above. The BKN Trace Core session APIs under /api/agent-observability/v1 accept gateway credentials only from trusted in-cluster services. They do not accept OAuth tokens or bak_ AppKeys; direct external calls receive 401 permission_denied. Context Loader derives the Operation idempotency identity on the server from request correlation, tool name, and normalized input. Callers must not submit operation_key. Network retries should reuse bkn-request-id or provide a stable X-OpenBKN-Client-Invocation-Id for the same logical call. This hint is used only for idempotency and has no role in identity, authorization, or data-isolation decisions.
